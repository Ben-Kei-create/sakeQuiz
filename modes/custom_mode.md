# カスタムモード(最初の3つの質問)

企画の最初に、AI がオーナーに3つの質問を出す。オーナーは**番号で答えるだけ**でよい(考える必要はない)。
答えは、アプリの設計を大きく左右する「縛り」になる。縛りがあるほど、味が出る。

## 質問の出し方(AI のルール)
- 3問をまとめて出す。各問は **4択**。AI が、そのアプリに合わせて**その時のおすすめ**を4つ作る(毎回変える。使い回さない)。
- 4つのうち、最もおすすめを**1番**に置き、理由を一言添える。
- オーナーは「1 / 3 / 2」のように番号で答える。「おまかせ」なら、全て1番(おすすめ)で進める。自由に書いてもよい。
- 質問以外の説明は最小限にする。
- 答えを受けたら、確認の質問はせず、そのまま設計に反映する。内容は `docs/mode_log.md` に1行で記録する。

## 3つの質問

### Q1. Era mode(時代の縛り)
その時代以降の技術・記述・表現を使わない。強制的に時代感を出す。
- 選択肢の作り方: アプリの題材に合う年代・時代を4つ(例: 1920年代 / 1960年代 / 1980年代 / 1990年代)。「縛りなし」は選択肢に入れない(入れたい時はオーナーが自由に書く)。
- 縛りの適用範囲(**見た目・文言・音・演出・モチーフ・UIの比喩**):
  - その時代以降に生まれた言葉、技術、機器、文化に触れない(例: 1980年代なら、スマホ、SNS、AI、アプリという語を、画面の文言に使わない)。
  - 色数、書体、質感、効果音、アニメーションの語彙を、その時代の表現に寄せる。
  - 操作の比喩も時代に合わせる(例: 昭和なら、ダイヤル、スタンプ、巻物、レコード)。
- 縛らないもの(常に守る): 実装に使う技術(Swift/SwiftUI など)、アクセシビリティ(文字サイズ、コントラスト、VoiceOver)、
  プライバシー、審査・法令・安全、ストア説明の事実性(ストアの文面は機能を正確に書く)。
- 時代の商標・ブランド・キャラクターを真似しない。

### Q2. Rule mode(ルールの縛り)
操作と体験を、一つの強いルールに絞る。機能を削る方向の縛り。
- 選択肢の作り方: アプリに合う縛りを4つ(例: 1日1回だけ / 片手の親指1本だけ / 画面を1枚だけ / 1回30秒で終わる / 文字を使わない / 戻るボタンがない)。
- 縛りの適用範囲: 画面数、操作の種類、セッションの長さ、継続の仕掛け、収益化のタイミング。
- 縛らないもの: 迷わず使える最低限の導線、アクセシビリティ、エラー時の復帰手段、設定(最低限)。

### Q3. Voice mode(語り口・世界観の縛り)
アプリ全体の「人格」と語り口を一つに決める。文言、効果音、アイコンのモチーフ、ストアの訴求まで統一する。
- 選択肢の作り方: アプリに合う人格・世界観を4つ(例: 寡黙な職人 / 研究所の記録係 / 旅の案内人 / 気まぐれな店主 / 古い図鑑)。
- 縛りの適用範囲: 画面の文言、通知、エラー文、結果の言い回し、音、アイコンの題材、スクリーンショットの見せ方。
- 縛らないもの: 重要な案内(購入、権限、プライバシー、エラーの原因)は、ふざけず、明確に書く。

## 縛りの優先順位
1. 審査・安全・個人情報・法令・アクセシビリティの最低ライン(常に100%)
2. オーナーの「変更不可」
3. **この3つの縛り(Q1〜Q3)**
4. 依存度ダイス(`randomdice.md`)で決まる設計の配分
5. その他の設計判断

縛りどうしが衝突したら、Q1 → Q2 → Q3 の順に優先する。ダイスの配分は、縛りの範囲内で適用する。

## 適用しない場面
- 既存アプリ診断モード(`review_prompts/existing_app.md`)では、オーナーが作り直しを望んだ時だけ、この質問を出す。
- バグ修正、審査対応の返信、申請キットの作成には、縛りを適用しない。

## 質問の出力例(形式)
```
最初に3つ、番号で答えてください(「おまかせ」なら全部1番です)。

Q1 Era mode(時代の縛り)
 1. 1980年代 … 〇〇な理由でおすすめ
 2. 1960年代
 3. 1920年代
 4. 1990年代

Q2 Rule mode(ルールの縛り)
 1. 1日1回だけ … 〇〇な理由でおすすめ
 2. 片手の親指1本だけ
 3. 画面を1枚だけ
 4. 1回30秒で終わる

Q3 Voice mode(語り口)
 1. 古い図鑑 … 〇〇な理由でおすすめ
 2. 寡黙な職人
 3. 旅の案内人
 4. 気まぐれな店主

例:「1 3 2」
```
