# 初回リリース・差別化プレイブック(自分用)

「必ず売れる秘策」は存在しない。ここにあるのは、**売れない確率を下げ、審査にも強くなる定石**。
差別化は、売れるためだけでなく、4.3(a)(b)・4.2.6 のリジェクト回避にも直結する。
企画時(段階1)に使い、`docs/competitor_notes.md` と併せて埋める。

## 1. 勝てる場所を選ぶ(企画)
- **狭く深く**: 「ワインクイズ」ではなく「ソムリエ試験の産地問題だけ」のように、誰向けかを1文で言えるまで絞る。
- **既存の不満から始める**: 競合アプリのレビュー(★1〜3)を20件読み、不満を3つ書き出す。それを直すのが差別化。
- **自分が使い続けられるテーマか**: 自分が2週間毎日使えないアプリは、ユーザーも使わない。
- **競合が弱い領域か**: 検索して上位が古い(更新が1年以上前)、レビューが少ない、デザインが古い領域は狙い目。
- **同じ型で量産しない**: 題材だけ変えた派生は、売れにくく、審査にも弱い。

## 2. 差別化の型(どれか1つを核にする。全部は狙わない)
| 型 | 内容 | 例 |
|---|---|---|
| 対象を絞る | 特定の人・目的に特化 | 資格試験対策、初心者専用 |
| 体験が違う | 遊び方・見せ方が別物 | 地図で当てる、写真で当てる、1日1問 |
| 続く仕組み | 毎日開く理由がある | 連続記録、復習(間違えた問題)、今日の1問 |
| 中身の質 | データ・解説が圧倒的 | 出典付きの解説、監修、豊富な問題数 |
| 見た目・世界観 | 一目で他と違う | 独自のイラスト、音、トーン |

核を1文にする: 「〇〇な人が、△△できる、唯一の□□」。1文にできなければ企画をやり直す。

## 3. 初回リリースの質(ここで評価が決まる)
- **最初の30秒**: 起動から最初の1問(最初の価値)まで、登録・説明・広告を挟まない。
- **ストア画像の1枚目**: 何のアプリで誰向けかを、文字大きめで1枚目に示す。1〜3枚目で伝わる構成にする。
- **名前とサブタイトル**: 検索される言葉(用途・ジャンル)を入れる。商標・資格名称は避ける。
- **キーワード**: 100文字を使い切る。同義語を並べ、アプリ名と重複する語は入れない。
- **説明文の冒頭**: 3行で価値が伝わるように。機能の羅列から始めない。
- **コンテンツ量**: 薄いと即座に離脱される。最低ラインを決めて(例: 問題数、モード数)、満たすまで出さない。
- **品質**: クラッシュなし、オフラインで動く、iPad で崩れない。初回レビューが★1だと取り返しにくい。

## 4. 継続・収益(設計時に決める。後付けは難しい)
- **継続の仕掛け**: 連続日数、復習、進捗の見える化、通知(許可を求めるのは価値を体験した後)。
- **広告は体験を壊さない場所に**: 結果画面など区切りで。回答中や起動直後は避ける。
- **課金の考え方**: 広告削除、追加コンテンツ、学習モードの解放など、「あると嬉しい」ものを課金にする。無料部分で価値を十分に体験させる。
- **評価依頼のタイミング**: 良い体験の直後(高得点、連続達成)に、システムの評価ダイアログを出す。起動直後や失敗直後は避ける。
- **レビューへの返信**: 最初の数十件には必ず返信する。

## 5. 初速をつくる(リリース前後)
- **TestFlight**: 10人以上に1〜2週間使ってもらい、直した記録を残す(審査の質問4にも使える)。
- **事前の接点**: SNS・コミュニティ(ワイン好き、受験者の集まり)で、開発中に画面を見せて反応を取る。
- **初週に集中**: 初週のダウンロードと評価が、検索順位の初速になる。リリース日を決めて、告知を初週にまとめる。
- **ローカライズ**: 日本語だけで始めてもよいが、英語の説明文・キーワードだけでも用意すると検索の入口が増える。
- **公開ページ**: サポート/プライバシーに加え、紹介ページを1枚用意し、SNSからのリンク先にする。

## 6. リリース後の運用
- 計測する指標: ダウンロード、起動日数(翌日/7日継続)、レビュー、クラッシュ。
- 最初の1か月は、レビューと継続率を見て、週1で小さく更新する。更新履歴(What's New)は具体的に書く。
- 伸びない時は、順に疑う: ①検索で出てこない(キーワード/名前) ②出ても押されない(画像/説明) ③入れても続かない(最初の30秒/継続の仕掛け)。

## 7. 避けること
- 他アプリの名前・ブランド・資格名称に寄せる(審査にも不利)。
- 評価を不正に水増しする、レビューを買う(規約違反)。
- 機能を足し続けて、核が見えなくなる。
- 数字を見ずに、感覚だけで更新する。
