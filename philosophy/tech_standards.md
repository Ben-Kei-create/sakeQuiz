# 技術・設計の標準方針

| 項目 | 標準 |
|---|---|
| iPhoneアプリ | Swift / SwiftUI |
| macOSアプリ | Swift / SwiftUI |
| 2D・3Dゲーム | Godot。必要に応じて Blender で素材制作 |
| Webサービス | Next.js など + Vercel |
| データ保存 | オフライン・端末内保存を優先 |
| バックエンド | 必要性が明確になるまで導入しない |
| AI機能 | アプリ内では、必須でなければ採用しない |
| テスト | ビルド、機能、画面表示、回帰テスト |
| リリース | 小さく公開し、利用結果から改善する |

## AI の役割分担
- **Claude Code**: 企画、実装、クオリティアップの担当。設計書(正本)に従って実装し、テストを実行し、品質を上げる。企画では、設計書を調べて磨く。
- **Codex**: 独立レビュー・クオリティアップの担当。**実装は書かない**。Codex への指示(`review_prompts/codex_review.md`)に従って、仕様との相違、UIの崩れ、回帰、セキュリティ、想定外、審査リスクをレビューし、改善案を出す。
- 流れ: Claude Code が企画・実装 → Codex がレビュー → Claude Code が修正・品質向上 → 必要なら再レビュー。
- 毎回の実装指示は短くし、「今回の変更範囲」だけを指定する。正本は詳細設計書。
- 企画の独自性と最終的な品質判断は、オーナーが握る。

## 詳細設計書の標準項目(コードを書く前に確定する)
1. 企画の目的、対象ユーザー
2. 機能の優先順位(やらないことも書く)
3. 全画面の構成
4. 画面遷移
5. 状態の変化
6. 永続化するデータ
7. エラー時・例外時の処理
8. デザイントークン(色、文字、余白、角丸、影、アニメ)
9. テスト観点
10. ストア公開要件(文面、スクリーンショット、課金表示、プライバシー)
11. 収益化と運用コストの見積もり

## 完了の定義
- **実装完了 ≠ リリース完了。**
- リリース完了 = 実機テスト、ストア文面、スクリーンショット、課金表示、プライバシー設定、審査の事前チェック(段階3)まで終わっていること。

## 再利用する部品(テンプレート化の候補)
ボタン・カードUI、データ保存、課金、設定画面、画像アセット管理、ストア申請文面。
見た目を全アプリで同じにするためではなく、作業を省くために共通化する。
