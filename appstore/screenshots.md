# スクリーンショット(Xcode のシミュレータで撮る)

## 原則
- **捏造しない。** 実際に動くアプリの画面だけを撮る。実在しない機能、加工で作った画面、未実装の機能を写さない。
- **テスト広告を写さない。** 「Test Ad」表示のあるテスト広告は、スクリーンショットに絶対に入れない(詳細は下)。
- 個人情報、開発用の表示(デバッグ表記、ダミーの文字、エラーログ)を写さない。
- 他アプリと酷似した構図・素材にしない。

## 事前準備
1. 撮影用の状態を用意する: サンプルデータ、進行度、入力値など、見栄えがよく、実際に起こり得る内容にする。
2. **撮影モード**(推奨): 起動引数 `-SCREENSHOT_MODE` のとき、広告の表示領域を出さず、サンプルデータを読み込む。
   - SwiftUI: `ProcessInfo.processInfo.arguments.contains("-SCREENSHOT_MODE")`
   - Xcode の Scheme の Arguments に追加して撮る。出荷時のビルドには含めない。
   - 広告を隠すのは撮影のためだけ。出荷版では広告は通常どおり表示する。
3. テスト広告の確認: 出荷用ビルドに、テスト用の広告ユニットIDが残っていないことを確認する(`3_submission.md` でも確認)。
   本番の広告IDを、開発中の自分の端末・シミュレータで操作(タップ)しない。

## 撮影の手順
1. 必要なデバイスの枠と枚数は、Apple公式の現行の仕様で確認する(固定のサイズを決め打ちしない)。
   https://developer.apple.com/jp/help/app-store-connect/reference/app-information/screenshot-specifications/
2. 提出に必要なサイズのシミュレータを選ぶ(iPad に対応するなら iPad も)。
3. ステータスバーを整える(推奨):
   `xcrun simctl status_bar booted override --time "9:41" --batteryState charged --batteryLevel 100 --cellularBars 4 --wifiBars 3`
   撮影後は `xcrun simctl status_bar booted clear` で戻す。
4. 画面を表示して撮る: シミュレータで Command + S、または
   `xcrun simctl io booted screenshot ファイル名.png`
5. 言語・外観を揃える。ライト/ダークは、アプリの系統に合う方に統一する(両方出すなら、同じ枚数で揃える)。
6. 保存: `docs/screenshots/{デバイス}/01-home.png` のように、連番と内容名を付ける。

## 構成(推奨)
1. 何のアプリで誰向けかが一目で分かる画面(1枚目が最重要)
2. 主要機能
3. 操作に対する画面の変化(成功・失敗など)
4. 差別化の機能
5. 結果・進捗・設定など
6. その他の実在する特徴

- 5〜6枚を目安にする。必須枚数は公式で確認する。
- 文字入れ(キャプション)をする場合は、短く事実だけを書く。日本語は `philosophy/fonts.md` の固定フォントを使う。誇張や、実在しない機能は書かない。
- Era / Voice mode を決めている場合は、その世界観に合わせて見せ方を統一する。

## 提出前チェック
- [ ] 必要なデバイス枠のサイズ・形式・枚数が公式の仕様に合っている
- [ ] 全ての画面が実際のアプリの動作と一致している(捏造なし)
- [ ] テスト広告、デバッグ表示、ダミーの文字、個人情報が写っていない
- [ ] ステータスバーが整っている
- [ ] 説明文・キャプションの内容が、実装済みの機能だけである
- [ ] 公開ページ用に縮小版(幅約480px、1枚約100KB以下)を作った
- [ ] 他アプリと酷似していない
