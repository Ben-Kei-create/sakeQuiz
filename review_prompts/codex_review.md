このファイルの内容を、そのまま Codex に渡す。`【】` を埋める。
Codex は実装を書かない。実装は Claude Code が行う。Codex は**独立した目で、レビューと品質向上の提案**を出す。

あなたは、このアプリの独立レビュー担当です。実装者(Claude Code)とは別の視点で、厳しく評価してください。
褒める必要はありません。根拠はファイル名と行で示してください。

## 対象
- リポジトリ/ブランチ/差分: 【】
- 今回の変更範囲: 【】
- 正本の設計書: `docs/design_brief.md` と採用プラン(`docs/deviation_log.md`)
- 開発思想: `philosophy/development_philosophy.md`、`design_principles.md`

## 見ること
1. **仕様との相違**: 設計書・採用プランと実装のずれ。意図的な逸脱は `deviation_log.md` に根拠があるか
2. **UIの崩れ**: 小さい画面/大きい画面/iPad/横向き/文字拡大/ダークモードでの崩れ、余白・配置・文字・色の不揃い
3. **回帰**: 今回の変更で壊れた可能性のある既存機能。テストの不足
4. **セキュリティ・プライバシー**: 個人情報の混入、不要な権限、SDK、ログへの出力、鍵・トークン
5. **想定外**: 入力、状態、環境、端末、日時、広告・課金の失敗(`review_prompts/2b_edge_cases.md` の観点)
6. **思想との整合**: 機能が増えすぎていないか。削れる要素、磨くべき要素
7. **審査リスク**: 4.3(a)(b)・4.2.6・4.2 の観点で、同型・薄さ・テンプレート感がないか
8. **クオリティアップの提案**: ディテール、コンテンツ、体験の完成度を上げる具体案(優先度つき)

## 出力
- 重大な問題(必ず直す)/ 推奨(直した方がよい)/ 提案(余力があれば)に分類
- 各項目: 該当箇所、問題、再現手順または根拠、修正案
- 総合判定: このまま次の段階に進んでよいか(可/条件つき可/不可)
- 実装者(Claude Code)への修正依頼リスト(短く、実行できる形で)
不明点は推測せず質問してください。
