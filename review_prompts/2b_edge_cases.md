# 段階2b: 想定外のバグ・想定外ユーザーの洗い出し(開発中。段階2と一緒に)

あなたは、意地悪なQAエンジニアと、多様なユーザー調査の担当者を兼ねています。
オーナーが想定していないバグ、想定していないユーザーを**自分で用意し**、それを使って
(A)品質を上げ、(B)コンテンツと機能の幅を広げ、(C)細かなディテールに反映してください。
指摘だけで終わらせず、直す・足す提案までを出してください。

## 対象
- リポジトリ/パス: 【】
- 現在の設計(`docs/design_brief.md`、採用プラン): 【】

## 1. 想定外のバグを用意する(コードを読んで、実際に起きうるものを挙げる)
次の観点で、再現手順つきで挙げる。推測だけでなく、該当ファイルと行を示す。
- 入力: 空、極端に長い、絵文字、全角/半角、改行、連打、素早い画面遷移
- 状態: 途中で閉じる、バックグラウンド復帰、タイマー中の中断、ストレージ満杯、データ破損、初回起動と2回目以降
- 環境: オフライン、機内モード、回線切断中の広告、低電力モード、通知拒否、権限拒否
- 端末: 小さい画面(SE)、大きい画面、iPad、横向き、分割表示、ダイナミックタイプ(文字拡大)、ダークモード
- 日時: タイムゾーン変更、日付の変わり目、端末時刻の改ざん、うるう年
- 地域・言語: 日本語以外の端末設定、右から左の言語、数字の書式
- 広告・課金: 広告の読み込み失敗、表示中の中断、課金の復元失敗、キャンセル
- 負荷: 大量データ、長時間起動、メモリ警告
- データ: 問題・コンテンツの誤り、重複、選択肢が1つしかない、正解が複数、出典のない主張

## 2. 想定外のユーザーを用意する(最低8人。実在しそうな具体像で)
例の方向性。毎回、このアプリに合わせて作り直す。
- 初心者、超上級者(すぐ満点を取る)、急いでいる人、子ども、高齢者
- 視覚・聴覚・運動に制約のある人、片手だけで使う人、画面を見ずに使う人
- 日本語が第一言語でない人、専門用語を知らない人
- 悪用する人(ルールの抜け道を探す、連打で稼ぐ)、設定を触りまくる人
- 想定の目的と違う目的で使う人(教材として、イベントの余興として、子どもに見せる、など)
- 何日も放置して戻ってくる人

各ユーザーについて、次を書く。
- 何を期待して開くか / どこでつまずくか / 離脱する理由 / 満足するポイント

## 3. 反映する(ここが目的)
- **品質**: 見つけたバグの修正案と、再発防止のテスト案(優先度つき)
- **ディテール**: 空の状態、エラー文言、読み込み中、ヘルプ、設定項目、アクセシビリティ、小さな演出
- **コンテンツの幅**: 想定外ユーザーが求めるものから、足すべきコンテンツ・モード・難易度・解説を提案
  (例: 初心者向けの導入、上級者向けの高難度、短時間モード、復習モード、読み上げ)
- **設計の見直し**: 想定外ユーザーが多数派に近いなら、設計書の方針を変える提案(逸脱ログに記録)

## 出力

- 想定外ユーザー一覧(表)
- 反映案(品質/ディテール/コンテンツ/設計)を、優先度順に
- 今回の実装に入れるもの / 次回以降に回すもの
- `docs/edge_cases.md` に記録する内容
